# Project constraints

- GoGogo is a playful, colorful travel planner focused on friends and welcoming solo travelers, families, and other groups.
- Keep three views: Itinerary (primary), Budget & Expenses, and Settle Up, with two content sections per view, a heading, and an introduction.
- Support cities, start date (From), days, trip currency, activities, expenses, and a copyable invitation summary.
- Generating a city itinerary must automatically populate editable activities for every day; extending a city adds plans only to new days. Keep offline templates clearly labeled and do not imply live recommendations or verified availability.
- Keep form inputs, selects, and buttons visually aligned with consistent control heights, while allowing responsive stacking.
- Start new trips without invented travelers, spending, or example placeholders. Preserve existing saved data and unsaved form drafts during view updates. Calculate planned estimates separately from actual expenses, allow selected-person splits, and update budget/settlement totals from user-entered data.
- App files: index.html, style.css, script.js only. No dependencies, CDN, remote assets, or build tools.
- Use semantic HTML, readable CSS, small vanilla JavaScript, responsive layouts, and keyboard-accessible controls with visible focus.
- Data stays in browser local storage. No live collaboration or payment processing.
- Keep all work in this project. Serve only on localhost; do not start a server unless requested.
- Do not install, create accounts, deploy, commit, or push unless explicitly requested.
- Preserve existing work. Check file references and JavaScript syntax; report remaining manual browser checks.
